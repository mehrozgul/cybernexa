Detection Rules Lab

In this practical lab, analyze authentication logs and apply a detection rule to identify suspicious repeated login failures.

Lab Type SOC Detection
Data Source Authentication Logs
Rule Failed Login Threshold
Status Ready

Detection Rule Configuration

The following rule will be applied to the sample authentication logs.

Event Login Failure
Threshold 5 Failed Attempts
Window 5 Minutes
Action Generate Alert

Sample Authentication Logs

Review the events before running the detection rule.

Time Username Source IP Event Status
10:01:12 admin 185.44.21.90 Login Attempt Failed
10:02:03 admin 185.44.21.90 Login Attempt Failed
10:02:45 admin 185.44.21.90 Login Attempt Failed
10:03:19 admin 185.44.21.90 Login Attempt Failed
10:04:07 admin 185.44.21.90 Login Attempt Failed

Detection Result

The rule analyzed the authentication events and identified a suspicious pattern.

🚨 ALERT GENERATED

Five failed login attempts were detected from the same source IP address within the defined five-minute window.

Source IP: 185.44.21.90

Possible activity: Brute-Force Authentication Attempt

Severity: Medium

Detection Analysis

Understand why the rule generated the alert.

01. Count Events

The rule counts failed authentication attempts associated with the same source IP address.

02. Check Threshold

The number of failures reaches the configured threshold of five events.

03. Generate Alert

Because the threshold is reached within the defined time window, the detection rule generates an alert.

Lab Completion

You have successfully applied a basic Detection Rule to authentication logs. The rule identified repeated failed login attempts from the same source and generated a security alert. In a real SOC environment, an analyst would continue by validating the alert, investigating the source, checking additional logs and determining whether the activity represents a genuine attack or a false positive.
