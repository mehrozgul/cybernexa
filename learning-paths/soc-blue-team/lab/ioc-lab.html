IOC Investigation Lab

IOC Investigation Lab

Practice identifying Indicators of Compromise, classify their type and understand how SOC analysts begin an IOC investigation.

Lab Objectives

By completing this practical exercise, you will practice basic IOC identification and investigation.

OBJECTIVE 01

Identify IOC

Recognize a technical artifact that may represent an Indicator of Compromise.

OBJECTIVE 02

Classify IOC

Determine whether the indicator is an IP, hash, domain, URL, file path or email indicator.

OBJECTIVE 03

Investigate

Understand the next steps used by an analyst to validate and correlate the indicator.

IOC Reference Examples

Use these examples to understand common IOC formats.

IP Address

Network address that may be associated with suspicious communication.

203.0.113.25

File Hash

A hash value can be used to identify a specific file.

44d88612fea8a8f36de82e1278abb02f

Domain

A domain may represent suspicious infrastructure.

suspicious-example.com

URL

A URL can be investigated for suspicious or malicious activity.

https://example.test/login

File Path

An unusual executable path may require endpoint investigation.

C:\Temp\payload.exe

Email

Suspicious sender addresses may be useful during phishing investigations.

security-alert@example.test

Practical Task

  1. Select an IOC Type.
  2. Enter a valid IOC value.
  3. Click Analyze IOC.
  4. Review the initial investigation result.
  5. Think about which logs or security tools could provide additional evidence.
  6. Remember that an IOC requires context and correlation before it can be treated as confirmed evidence of compromise.

Lab Completed

You have practiced the basic process of identifying and classifying an Indicator of Compromise. In a real SOC, analysts would continue by validating the IOC, correlating it with logs and other evidence, and determining the appropriate response.
