What is IOC?

Indicators of Compromise (IOCs) are pieces of technical evidence that can indicate a system, account or network may have been involved in malicious activity.

Definition

Understand the basic meaning of an Indicator of Compromise.

Core Definition

An Indicator of Compromise (IOC) is a piece of evidence or observable artifact that may indicate malicious activity, a security breach, or compromise of a system or network.

How IOCs Work

Security teams use IOCs as investigation clues when analyzing suspicious activity.

During a security investigation, analysts collect evidence from different sources such as system logs, network traffic, endpoint security tools and security monitoring platforms.

Some of the collected artifacts may match known malicious activity. These artifacts can then be treated as Indicators of Compromise and investigated further.

For example, a suspicious IP address, a malicious file hash, an unusual domain or a known malicious file path may provide useful evidence during an investigation.

An IOC does not automatically prove that an attack occurred. Analysts normally correlate it with additional evidence, context and activity before reaching a conclusion.

Common Types of IOCs

Different types of technical artifacts can be used as Indicators of Compromise.

IOC TYPE 01

IP Address

A suspicious source or destination IP address associated with potentially malicious communication.

203.0.113.25
IOC TYPE 02

File Hash

A cryptographic hash can identify a specific file and help analysts compare it with known malicious samples.

SHA256: a91f...72bc
IOC TYPE 03

Domain

A suspicious domain may indicate communication with malicious infrastructure.

suspicious-example.com
IOC TYPE 04

URL

A suspicious URL may be associated with phishing, malware delivery or command-and-control activity.

https://example.test/login
IOC TYPE 05

File Path

An unusual or suspicious file location can provide evidence during endpoint investigation.

C:\Temp\payload.exe
IOC TYPE 06

Email Indicator

Suspicious sender addresses, subjects or attachments can provide useful investigation evidence.

invoice-update@example.test

Why IOCs Matter

IOCs help SOC analysts organize and investigate technical evidence related to suspicious activity.

01 — DETECTION

Find Suspicious Activity

IOCs can be searched across logs, endpoints and network data to identify potentially related activity.

02 — INVESTIGATION

Connect Evidence

Matching an IOC across multiple systems can help analysts understand whether different events may be related.

03 — RESPONSE

Support Security Actions

Validated IOCs can help security teams decide where additional investigation or defensive action is required.

IOC Investigation Flow

A simplified workflow used when analyzing a potential IOC.

01 Collect

Gather technical evidence.

02 Validate

Check the IOC and its context.

03 Correlate

Search related logs and events.

04 Investigate

Determine possible impact.

05 Respond

Apply appropriate security actions.

Key Concepts

Important IOC terms to remember.

IOC: An observable artifact that may indicate compromise.
Hash: A value used to identify a specific digital file.
IP Address: A network address that may be associated with suspicious communication.
Domain: A domain name that may be associated with suspicious infrastructure.
Correlation: Comparing an IOC with other events and evidence.
Context: Additional information needed to understand the meaning of an IOC.

Summary

Indicators of Compromise are technical artifacts that can provide evidence of potentially malicious activity. Common IOCs include IP addresses, file hashes, domains, URLs, file paths and suspicious email indicators. SOC analysts collect, validate and correlate these indicators with other evidence during security investigations. An IOC should be interpreted in context rather than treated as automatic proof of compromise.
