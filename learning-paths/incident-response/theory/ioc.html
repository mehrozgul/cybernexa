What are Indicators of Compromise?

Indicators of Compromise are observable signs that may indicate a security breach, malicious activity or a compromised system. Security analysts use IOCs to investigate and detect suspicious activity.

Definition

First, understand the core meaning of an Indicator of Compromise.

Core Definition

An Indicator of Compromise (IOC) is a piece of observable evidence that may indicate malicious activity or that a system, account or network has been compromised.

How IOCs Work

Security analysts use observable evidence to investigate suspicious activity and identify possible compromises.

During a security incident, analysts collect evidence from systems, networks, applications and security monitoring tools.

Some pieces of evidence may indicate that malicious activity has occurred. These can include suspicious IP addresses, malicious domains, file hashes, unusual processes or unexpected changes to systems.

Analysts compare these indicators with available logs, alerts and other evidence to determine whether the activity is related to a security incident.

IOCs can therefore help security teams detect, investigate and track suspicious activity during incident response.

Common IOC Types

IOCs can appear in different forms depending on the type of activity being investigated.

IOC 01

IP Address

A suspicious IP address may be associated with malicious communication, command-and-control traffic or an unauthorized connection.

203.0.113.25
IOC 02

Domain

A suspicious domain may be associated with phishing, malware delivery or other malicious infrastructure.

suspicious-example.com
IOC 03

File Hash

A cryptographic hash can be used to identify a specific file and compare it with known malicious samples.

SHA256: a84f...92cd
IOC 04

Email Indicator

Suspicious sender addresses, subjects or links can provide useful evidence during phishing investigations.

attacker@example.net
IOC 05

File Path

Unexpected files or suspicious locations may provide evidence of malware or unauthorized activity.

C:\Temp\suspicious.exe
IOC 06

Process

An unusual process or command execution can become an indicator when it is inconsistent with normal activity.

powershell.exe -enc ...

Why IOCs Matter

IOCs provide useful evidence that can support security investigation and detection activities.

REASON 01

Detect Suspicious Activity

Security tools can use known indicators to identify activity that may require investigation.

REASON 02

Investigate Incidents

Analysts can search logs and systems for matching indicators to understand the scope of an incident.

REASON 03

Track Threat Activity

Indicators can help analysts identify related activity across systems and security monitoring sources.

Simple Example

Consider a suspicious connection detected during monitoring.

🚨 Possible IOC

A workstation repeatedly communicates with an unfamiliar external IP address that is not normally used by the organization.

✓ Analyst Investigation

The analyst checks network logs, identifies the process responsible for the connection, compares the IP with available threat intelligence and investigates related activity before deciding on the appropriate response.

Key Concepts

Important terms to remember for this topic.

IOC: Observable evidence that may indicate a compromise or malicious activity.
IP Address: A network address that may become suspicious when associated with malicious communication.
Domain: A domain name that may be associated with phishing or malicious infrastructure.
File Hash: A value used to identify a specific file.
Correlation: Comparing an indicator with other logs, alerts or evidence to understand its significance.
Validation: Checking whether an indicator is reliable and relevant to the investigation.

Summary

Indicators of Compromise are observable pieces of evidence that may indicate malicious activity or a compromised system. Common IOCs include IP addresses, domains, file hashes, suspicious email indicators, file paths and unusual processes. Security analysts collect and validate these indicators, investigate related activity, correlate evidence and use the findings to support incident response and security detection.
