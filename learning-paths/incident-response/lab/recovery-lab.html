Incident Recovery Lab

Practice the recovery phase of Incident Response by restoring an affected system from a clean backup, validating the system and monitoring it after recovery.

Difficulty Beginner
Category Incident Response
Lab Type System Recovery
Objective Restore & Validate
Lab Progress 0 / 5 tasks completed

Lab Scenario

Read the scenario before performing the recovery tasks.

⚠️ Compromised Server

A company's internal application server was compromised during a cybersecurity incident. The security team has already completed containment and eradication. The malicious software has been removed and the server is ready for recovery.


Your task is to simulate the recovery process by checking the system state, restoring clean data, validating the system, reconnecting it to the network and monitoring the restored environment.

Task 01 — Assess the System

First determine whether the system is ready for recovery.

01
Check system status

In a real environment, the security team checks the affected system and confirms that the threat has been removed before beginning restoration.

Linux Terminal
systemctl --failed
Expected Output:

No failed units are detected, or the remaining failed services have been investigated and are unrelated to the incident.

Task 02 — Identify a Clean Backup

Recovery should use a known-good backup whenever possible.

02
Check available backups

Before restoring data, identify a backup that was created before the incident and is known to be clean.

Linux Terminal
ls -lah /backup/
Expected Output:

backup-2026-09-20.tar.gz
backup-2026-09-22.tar.gz
backup-2026-09-24-clean.tar.gz

Select a backup that predates the incident and has been verified as clean.

Task 03 — Restore Clean Data

Restore the affected data from the selected clean backup.

03
Extract the clean backup

In this simulated environment, restore the application data from the clean backup archive.

Linux Terminal
tar -xzf /backup/backup-2026-09-24-clean.tar.gz -C /restore/
Expected Output:

The clean backup is extracted into the recovery directory without errors.

Task 04 — Validate the Recovered System

A recovered system must be checked before reconnecting it to production.

04
Verify restored files

Check that the restored files exist and that the recovery directory contains the expected application data.

Linux Terminal
ls -lah /restore/
Expected Output:

Application files and configuration files should be present.

The security team should also verify that the restored system does not contain the original threat.

Task 05 — Monitor After Recovery

Monitoring is important after the system returns to operation.

05
Check recent system activity

Review recent system events and look for unusual activity after restoration.

Linux Terminal
journalctl --since "30 minutes ago"
Expected Output:

Review recent events for suspicious logins, unexpected services, abnormal errors or other indicators of compromise.

No suspicious activity should remain before the system is considered fully recovered.
