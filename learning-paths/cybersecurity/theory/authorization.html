CYBERSECURITY FUNDAMENTALS

Authorization

Learn how authorization controls what an authenticated user is allowed to access and what actions that user is permitted to perform.

What is Authorization?

Authorization is the security process of determining what resources a user, device or application is allowed to access and what actions it is allowed to perform.

Why Authorization Matters

Authentication verifies who a user is, while authorization determines what that authenticated user can do. Proper authorization prevents users from accessing resources or performing actions beyond their assigned permissions.

  • Protects sensitive resources from unauthorized access.
  • Limits users to the permissions they actually need.
  • Helps prevent privilege abuse.
  • Supports least-privilege security.
  • Separates normal-user and administrative permissions.

Authentication vs Authorization

🔐

Authentication

Determines who the user is. For example, a username and password can be used to verify a user's identity.

🛡️

Authorization

Determines what the authenticated user is allowed to access or perform.

Common Authorization Models

👥

RBAC

Role-Based Access Control assigns permissions according to roles such as Admin, Manager or Employee.

📋

ABAC

Attribute-Based Access Control makes decisions using attributes such as user role, department, resource and context.

👤

DAC

Discretionary Access Control allows resource owners to determine who can access their resources.

🏢

MAC

Mandatory Access Control uses centrally defined security policies and classifications to control access.

Role-Based Authorization

In Role-Based Access Control, permissions are assigned to roles instead of being individually assigned to every user.

Example: University System

An Admin may manage users and system settings. A Teacher may manage course material and grades. A Student may view courses and their own grades. Each role receives only the permissions required for its responsibilities.

Principle of Least Privilege

The principle of least privilege means that a user, application or system should receive only the minimum permissions required to perform its legitimate task.

  • Reduces unnecessary access.
  • Limits the impact of compromised accounts.
  • Reduces accidental changes to sensitive resources.
  • Helps control privilege escalation risks.

Examples of Authorization

📄

File Access

A user may be allowed to read a file but not modify or delete it.

🗄️

Database Access

A normal employee may view selected records while an administrator can manage them.

🌐

Web Application

A student may view their profile while an administrator may manage user accounts.

⚙️

System Settings

Only authorized administrative roles should be allowed to change sensitive settings.

Security Best Practices

  • Apply least privilege.
  • Use role-based access where appropriate.
  • Review permissions regularly.
  • Remove unnecessary privileges.
  • Protect administrative accounts.
  • Log important authorization decisions.
  • Deny access by default when appropriate.

Key Concepts

🎭

Role

A category assigned to a user that determines which permissions they receive.

🔑

Permission

An allowed operation such as read, write, update or delete.

📦

Resource

A protected object such as a file, database, page, API or system setting.

🛡️

Least Privilege

Giving only the minimum permissions necessary for a legitimate task.

Summary

Authorization determines what an authenticated user is allowed to access and what actions they can perform. RBAC, ABAC, DAC and MAC are common authorization approaches. Strong authorization uses least privilege, appropriate roles, permission reviews and proper access controls.
