CYBERSECURITY FUNDAMENTALS

Hashing

Learn how hashing converts data into a fixed-length value, why hashes are useful in cybersecurity and how they are used for integrity and password protection.

What is Hashing?

Hashing is a one-way process that converts input data into a fixed-length value called a hash or hash digest. A small change in the original data normally produces a different hash value.

Why Hashing Matters

Hashing is important because it can be used to verify data integrity and protect stored passwords. Instead of storing a password in plain text, a system can store a password hash and compare a newly calculated hash during login.

  • Helps verify whether data has been changed.
  • Supports secure password storage when used correctly.
  • Helps detect accidental or unauthorized modification.
  • Used in digital signatures and many security systems.

How Hashing Works

1️⃣

Input

The original data, such as a password, message or file, is provided as input.

⚙️

Hash Function

A cryptographic hash function processes the input data according to its algorithm.

#️⃣

Hash Digest

The function produces a fixed-length output called a hash digest.

🛡️

Verification

A system can calculate a hash again and compare it with the expected hash.

Important Properties of Cryptographic Hashing

One-Way

A secure cryptographic hash function is designed so that obtaining the original input from the hash is computationally impractical.

Deterministic

The same input produces the same hash when the same hash algorithm and parameters are used.

Avalanche Effect

A small change in the input should cause a significant change in the resulting hash.

Collision Resistance

It should be computationally difficult to find two different inputs that produce the same hash.

Common Hash Algorithms

🔐

SHA-256

A member of the SHA-2 family that produces a 256-bit digest and is widely used today.

🔒

SHA-512

A SHA-2 algorithm that produces a 512-bit digest.

⚠️

MD5

An older 128-bit hash algorithm that is considered unsuitable for modern security applications because practical collision attacks exist.

⚠️

SHA-1

An older hash algorithm that is no longer recommended for security-sensitive applications.

Hashing and Password Security

Passwords should not normally be stored as plain text. Password-specific password hashing functions are designed to make large-scale password guessing more expensive.

  • Use a unique salt for each password.
  • Use a password hashing algorithm designed for this purpose.
  • Do not treat simple fast hashes such as SHA-256 as a complete password-storage solution by themselves.
  • Protect password databases and access to authentication systems.

Hashing vs Encryption

#️⃣

Hashing

Primarily one-way. It produces a digest used for integrity verification and other security purposes.

🔑

Encryption

Designed to protect confidentiality and can be reversed with the appropriate key.

Simple Example

Example: File Integrity

Suppose a software developer publishes a file together with its SHA-256 hash. A user can calculate the SHA-256 hash of the downloaded file and compare the two values. If the values match, this provides evidence that the file contents are unchanged since the published hash was generated.

Key Concepts

🧂

Salt

Random data added to password hashing so that identical passwords do not produce identical stored hashes.

📦

Digest

The fixed-length output produced by a hash function.

Summary

Hashing converts input data into a fixed-length digest. Cryptographic hashes are useful for integrity verification, password protection and security protocols. Hashing is fundamentally different from encryption because hashing is designed as a one-way transformation.
