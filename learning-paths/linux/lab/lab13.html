Lab 13 - Linux Logs

In this practical lab, you will learn how to view Linux system logs, inspect journal entries, search log files, monitor new events, examine authentication activity and use logs for troubleshooting and basic cybersecurity analysis.

Platform Ubuntu / Debian Linux
Tool Linux Terminal
Level Beginner
LOG

Lab Objective

The objective of this lab is to understand how Linux records system and security events in logs and how these records can be viewed, searched and monitored.

What You Will Practice Viewing system logs, using journalctl, checking authentication logs, searching logs with grep, monitoring logs with tail, checking boot events and identifying useful security information.
01
$

Open the Linux Terminal

Open the Terminal application in your Ubuntu or Debian-based Linux system.

Instruction Press Ctrl + Alt + T to open the terminal.
Expected Result A Linux terminal window should appear and you should be ready to inspect system logs.
02
/

Explore the Linux Log Directory

Many Linux systems store traditional log files inside the /var/log directory.

Linux Terminal 
ls -lah /var/log
Explanation The command lists files and directories stored under /var/log. These may include system, authentication and application-related logs.
Expected Result A list of log files and directories should be displayed. The exact files depend on your Linux distribution and configuration.
03
J

View System Logs with journalctl

On Linux systems using systemd, journalctl is commonly used to view system journal entries.

Linux Terminal 
journalctl
Explanation The command displays journal entries recorded by the system journal. Depending on system permissions, some entries may require elevated privileges.

If necessary, you can use: sudo journalctl
Expected Result Log entries containing timestamps, services, processes and system messages should appear.
04
B

View Logs from the Current Boot

Use the -b option with journalctl to view messages from the current system boot.

Linux Terminal 
journalctl -b
Option Meaning -b tells journalctl to display messages associated with the current boot session.
Expected Result You should see messages generated during the current Linux boot process.
05
S

View Logs for a Service

journalctl can be used to inspect logs generated by a particular system service.

Linux Terminal 
journalctl -u ssh.service
Explanation The -u option filters journal entries for a specific systemd service.

On Ubuntu/Debian systems with OpenSSH installed, the service is commonly named ssh.service.
Expected Result If the SSH service is installed and has generated journal entries, related log messages should be displayed. If the service does not exist, journalctl will report that the unit could not be found.
06
→

Monitor New Log Entries

Use journalctl -f to follow new journal entries as they are created.

Linux Terminal 
journalctl -f
Explanation The command continuously displays new journal entries in real time.

Press Ctrl + C to stop monitoring.
Expected Result New journal messages appear as they are generated by the system.
07
F

View the End of a Log File

The tail command displays the last part of a file. It is useful when checking recent log entries.

Linux Terminal 
sudo tail /var/log/syslog
Explanation This command displays the most recent part of the selected log file.

The file may not exist on every Linux installation. If it does not exist, use journalctl instead.
Expected Result Recent log messages from the selected file should be displayed when the file exists.
08
T

Monitor a Log File in Real Time

The -f option allows tail to continuously monitor a log file for new entries.

Linux Terminal 
sudo tail -f /var/log/syslog
Instruction Leave the command running and observe new messages.

Press Ctrl + C when you want to stop.
Expected Result New lines added to the log file should appear automatically.
09
G

Search Logs with grep

The grep command can search log files for specific words or patterns.

Linux Terminal 
sudo grep -i "warning" /var/log/syslog
Option Meaning -i makes the search case-insensitive, so uppercase and lowercase forms can both match.
Expected Result Lines containing the word warning should be displayed when matching entries exist.
10
A

Inspect Authentication Logs

Authentication logs can contain information about login attempts and other authentication events.

Linux Terminal 
sudo tail /var/log/auth.log
Explanation On many Ubuntu and Debian systems, /var/log/auth.log contains authentication-related events such as login activity and privilege-related messages.

The exact log location depends on the Linux distribution and logging configuration.
Expected Result Recent authentication-related log entries should be displayed if the file exists.
11
!

Search for Failed Authentication Events

Search authentication logs for entries containing the word failed.

Linux Terminal 
sudo grep -i "failed" /var/log/auth.log
Security Connection Failed authentication events can be useful during security investigations. Analysts should consider timestamps, usernames, source addresses and surrounding events before drawing conclusions.
Expected Result Matching authentication entries should be displayed when failed events exist.
12
S

View System Messages

On systems that maintain a traditional /var/log/syslog file, you can inspect recent system messages.

Linux Terminal 
sudo tail /var/log/syslog
Alternative If your system does not use /var/log/syslog, use journalctl to inspect the system journal.
Expected Result Recent system messages should be displayed when the log file is available.

journalctl -b Shows messages from the current boot.
journalctl -u ssh.service Displays journal entries for the SSH service.

Why Linux Logs Matter in Cybersecurity

Logs provide technical records of system, authentication and application activity. Security professionals can use these records during monitoring, troubleshooting and incident investigation.

  • Logs can help identify authentication activity.
  • Failed login events may be useful during security investigations.
  • System logs can help troubleshoot unexpected behavior.
  • journalctl can provide centralized system journal information.
  • grep can help locate specific patterns inside large log files.
  • tail can help monitor recent log activity.
  • Log entries should be analyzed with timestamps and surrounding context.

⚠

Important Log Analysis Note

A single log entry is a technical clue and does not automatically prove that an attack occurred. Security analysts normally examine timestamps, users, source addresses, services and related events before reaching a conclusion.

Security Practice Analyze logs only on systems and environments that you are authorized to access. Do not attempt to access, modify or delete another person's logs without permission.
