01

What is HTTP?

Core Definition

HTTP (Hypertext Transfer Protocol) is an application-layer protocol used for communication between web clients and web servers. A browser sends an HTTP request and the server returns an HTTP response containing information such as HTML, CSS, JavaScript, images or data.

02

How HTTP Communication Works

Web communication normally follows a request-response model. The client requests a resource and the server processes that request before returning a response.

Browser Creates the request
HTTP Request Method, URL and headers
Web Server Processes request
HTTP Response Status and content
Browser Displays the result
03

HTTP Request

An HTTP request contains information that tells the server what the client wants to do. Common request components include the HTTP method, requested resource, headers and sometimes a body.

GET

Requests a resource from the server. It is commonly used when retrieving a web page or other resource.

POST

Sends data to the server, commonly for form submission or creating server-side data.

PUT

Commonly used to replace or update a resource.

DELETE

Requests deletion of a resource when the server supports that operation.

04

HTTP Response

The server sends an HTTP response after processing a request. The response normally contains a status code, headers and optionally a response body.

Status Meaning
200 OK The request was successfully processed.
301 / 302 Redirects the client to another location.
400 Bad Request The request contains invalid information.
401 Unauthorized Authentication is required or has failed.
403 Forbidden The server refuses access to the resource.
404 Not Found The requested resource could not be found.
500 Server Error An error occurred while processing the request.
05

What is HTTPS?

Secure HTTP

HTTPS (Hypertext Transfer Protocol Secure) is HTTP protected using TLS (Transport Layer Security). TLS helps provide confidentiality, integrity and authentication for communication between the client and server.

06

HTTP vs HTTPS

Feature HTTP HTTPS
Transport Security Not protected by TLS Protected by TLS
Encryption No TLS encryption Traffic is protected by TLS
Integrity No TLS integrity protection TLS provides integrity protection
Authentication No TLS server authentication TLS certificates help authenticate the server
07

Why HTTPS Matters in Web Security

🔐
Confidentiality TLS helps prevent unauthorized parties from reading protected web traffic in transit.
🛡
Integrity TLS helps detect unauthorized modification of protected data while it is being transmitted.
✓
Server Authentication TLS certificates help a browser verify the identity associated with a website.
08

Important Security Concepts

HTTPS protects data while it travels between the client and server, but it does not automatically make the entire application secure. Application vulnerabilities can still exist.

⚠ HTTPS IS NOT A COMPLETE SECURITY SOLUTION

A website can use HTTPS and still contain vulnerabilities such as SQL injection, cross-site scripting, broken access control, insecure authentication or unsafe file handling. HTTPS protects the communication channel; application security requires additional controls.

Module Summary

Understand the Traffic. Secure the Channel.

HTTP provides the basic request-response mechanism used by the web, while HTTPS adds TLS protection to that communication. Understanding requests, responses, methods, status codes and TLS is essential for analyzing modern web applications and learning web security.
