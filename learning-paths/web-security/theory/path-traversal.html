01

What is Path Traversal?

Core Definition

Path Traversal is a web security vulnerability that occurs when an application does not properly validate user-controlled file paths. An attacker may attempt to manipulate a path so that the application accesses a file outside its intended directory.

02

How Path Traversal Happens

Many web applications provide functionality such as downloading reports, displaying images, loading documents or retrieving configuration files.

If the application directly uses a user-supplied filename without proper validation, the input may influence the filesystem path selected by the server.

01 — User Input A filename or resource identifier is supplied through a request.
02 — Unsafe Handling The server combines the input with a filesystem path without sufficient validation.
03 — Unauthorized Resource The application may access a resource outside its intended directory.
03

Why Path Traversal is Dangerous

The impact depends on the application's permissions and the files that are reachable from the vulnerable functionality.

Information Disclosure Sensitive application or configuration information may become accessible.
Credential Exposure Improperly protected secrets or credentials may be exposed.
Application Compromise In severe cases, exposed information may contribute to further compromise.
04

Common Root Causes

Untrusted Input File paths are accepted directly from users.
Weak Validation The application checks extensions but not the complete resolved path.
Unsafe File APIs Server-side filesystem functions receive uncontrolled path information.
05

Secure Development

Developers should never assume that a filename supplied by a client is safe. File access should be constrained to an explicitly permitted directory.

const baseDirectory = "/application/uploads/"; const requestedFile = getUserInput(); const resolvedPath = resolve(baseDirectory, requestedFile); if (!resolvedPath.startsWith(baseDirectory)) { denyRequest(); }

The exact implementation depends on the programming language and framework. The important security principle is to resolve and validate the final path rather than trusting raw user input.

06

Security Controls

Allowlisting Permit only known files or identifiers instead of accepting arbitrary paths.
Canonicalization Resolve the final filesystem path before authorization.
Least Privilege Run applications with only the filesystem permissions they actually require.
07

Authorized Testing Scenario

In a controlled Web Security laboratory, a training application may intentionally contain an unsafe file-reading feature. Students can use predefined sandbox resources to understand how path validation affects application behavior.

⚠ AUTHORIZED ENVIRONMENT ONLY

Path Traversal testing should only be performed against applications and systems that you own or have explicit permission to test. The CyberNexa lab uses simulated resources and does not access the student's real operating system.

Module Summary

Validate the Path. Protect the Resource.

Path Traversal occurs when untrusted path information can influence server-side file access outside the intended directory. Strong input validation, canonical path checking, allowlisting and least-privilege permissions are important defenses against this vulnerability.
