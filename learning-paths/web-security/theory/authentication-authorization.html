Authentication & Authorization

01

What is Authentication?

Identity Verification

Authentication is the process of verifying who a user, device or system claims to be. In a web application, authentication commonly occurs when a user provides credentials such as a username and password. Modern systems may also use MFA, passkeys, certificates or other authentication mechanisms.

02

What is Authorization?

Permission Control

Authorization determines what an authenticated user is allowed to access or perform. After a system knows the identity of a user, it checks permissions, roles or policies before allowing access to a protected resource.

03

Authentication vs Authorization

These two concepts work together, but they answer different security questions.

IDENTITY

Authentication

Answers: "Who are you?"

Example: A user signs in with valid credentials and the application verifies the identity.

PERMISSION

Authorization

Answers: "What are you allowed to do?"

Example: An authenticated employee can view their own profile but cannot access administrator functions.

04

Authentication & Authorization Flow

A simplified web application security flow can be understood as a sequence of identity verification followed by permission checking.

01. Login User submits authentication information.
02. Verify Server validates the authentication data.
03. Identity Application establishes the authenticated user context.
04. Permission Server checks whether the requested action is allowed.
05

Security Controls

Secure web applications use multiple controls to reduce the risk of account compromise and unauthorized access.

🔐
Strong Authentication Use strong authentication mechanisms and avoid weak or reused credentials.
🛡
Multi-Factor Authentication Add another verification factor to reduce the impact of stolen passwords.
🎯
Server-Side Authorization Permission checks should be enforced on the server rather than relying only on the user interface.
📋
Least Privilege Users should receive only the permissions necessary for their legitimate tasks.
⏱
Session Management Applications should securely manage authenticated sessions and invalidate them appropriately.
06

Professional Example

Imagine a university web portal containing student and administrator accounts. A student successfully signs in with valid credentials.

AUTHENTICATED USER

The successful login establishes the user's identity. The application then checks the user's role and permissions. The student may be allowed to view their own academic information, while administrator-only functions remain unavailable.

07

Important Security Boundary

⚠ ACCESS CONTROL MUST BE ENFORCED SERVER-SIDE

Hiding a button or page element in the browser does not provide real authorization. A secure application must verify permissions on the server whenever a protected resource or action is requested.

08

Key Terms

Identity

Information representing a user or system within an application.

Credential

Information used to prove an identity, such as a password or authentication factor.

Role

A category that can be associated with a set of permissions.

Permission

An allowed action or resource access granted by an authorization policy.

Module Summary

Verify Identity. Control Access.

Authentication establishes who a user is, while authorization determines what that user is allowed to access or perform. Secure web applications use strong authentication, secure session management, server-side authorization and least-privilege principles to protect sensitive resources.
