01

What is a Cookie?

Core Definition

A cookie is a small piece of data that a website asks the browser to store. The browser can send that cookie back to the same website with later HTTP requests. Cookies allow web applications to maintain useful state across otherwise independent HTTP requests.

02

Why Do Websites Use Cookies?

HTTP is fundamentally stateless. Without some mechanism for maintaining state, a server would normally treat each request as an independent interaction.

Cookies provide one common mechanism for associating multiple requests with a browser or application state.

USE 01

Sessions

A session identifier can be stored in a cookie so the server can associate requests with a session.

USE 02

Preferences

Websites can remember selected preferences such as language or interface settings.

USE 03

Authentication State

Applications can use secure session cookies to maintain an authenticated browser session.

03

How Cookies Work

A common cookie flow begins when a server sends a Set-Cookie response header. The browser stores the cookie according to its attributes and may include it in later requests to the appropriate origin.

STEP 01
Request Browser sends an HTTP request to a website.
STEP 02
Response Server responds and may set a cookie.
STEP 03
Storage Browser stores the cookie according to its rules.
STEP 04
Return Browser may send the cookie with later requests. 
HTTP/1.1 200 OK
Set-Cookie: sessionId=abc123; Secure; HttpOnly; SameSite=Lax

Later Request:

Cookie: sessionId=abc123
04

Important Cookie Attributes

🔒
Secure Instructs the browser to send the cookie only over secure HTTPS connections.
🛡
HttpOnly Prevents client-side JavaScript from directly accessing the cookie through document.cookie.
🌐
SameSite Controls when cookies are sent in cross-site contexts and can help reduce cross-site request risks.
⏱
Expires / Max-Age Controls how long a cookie remains available before it expires.
05

Cookies and Web Security

Cookies can contain security-sensitive information, especially when they are used for session management. Therefore, cookie configuration is an important part of web application security.

⚠ SECURITY NOTE

Sensitive session cookies should normally use appropriate security attributes such as Secure, HttpOnly and a suitable SameSite policy. Applications should also use HTTPS and protect authentication mechanisms on the server side.

06

Cookies vs Local Storage

COOKIES

Automatically Sent

Cookies can be automatically included with matching HTTP requests.

LOCAL STORAGE

JavaScript Controlled

Local Storage is accessed through browser-side JavaScript and is not automatically sent as an HTTP request header.

SECURITY

Different Controls

Cookies provide attributes such as HttpOnly, Secure and SameSite that localStorage does not.

07

Key Security Concepts

✓
Use HTTPS Protect data transmitted between browser and server using TLS.
✓
Protect Session Cookies Apply appropriate security attributes to authentication-related cookies.
✓
Avoid Sensitive Data Do not place unnecessary sensitive information directly inside client-side cookies.
Module Summary

Cookies Connect Browser State with Web Requests.

Cookies are an important part of modern web applications. They allow websites to maintain state across HTTP requests, support sessions and remember preferences. From a security perspective, attributes such as Secure, HttpOnly and SameSite are essential concepts for protecting cookie-based application state.
