01

What is CSRF?

Core Definition

Cross-Site Request Forgery (CSRF) is a web security vulnerability in which an attacker attempts to cause a user's browser to send an unintended request to a web application where the user is already authenticated.

02

How CSRF Works

CSRF becomes possible when a web application trusts browser credentials such as cookies without requiring additional proof that the request was intentionally generated by the legitimate application.

STEP 01

User Logs In

The browser establishes an authenticated session with the web application.

STEP 02

Session Exists

The browser may automatically attach authentication information to requests.

STEP 03

Unwanted Request

A malicious site attempts to cause an unintended state-changing request.

STEP 04

Server Validates

Proper CSRF defenses reject requests that cannot prove legitimate origin or intent.

03

CSRF Attack Model

A typical CSRF scenario involves a trusted user, a vulnerable web application and an untrusted external website or request source.

👤 Victim

The user is already authenticated to a target web application.

🌐 Target Application

The application accepts sensitive requests without sufficient request validation.

⚠ Untrusted Origin

An external source attempts to trigger an unintended request.

04

Why CSRF Matters

CSRF is especially relevant to applications that perform important state-changing actions through authenticated browser requests.

!
Account Changes Sensitive account settings should not be changed through an unverified request.
!
Financial Operations Sensitive transactions require strong request validation.
!
Administrative Actions Privileged actions should require trustworthy request context.
05

How to Prevent CSRF

Modern applications normally combine multiple defensive mechanisms rather than relying on a single control.

🔑
CSRF Tokens Generate an unpredictable token and validate it with sensitive requests.
🍪
SameSite Cookies Configure cookies using an appropriate SameSite policy to reduce cross-site request risks.
🌐
Origin Validation Validate trusted request origins where appropriate for the application's architecture.
🛡
Re-authentication Require stronger confirmation for highly sensitive operations.
06

Important Security Note

⚠ AUTHORIZED WEB SECURITY LAB ONLY

CSRF concepts should be practiced only on your own applications, intentionally vulnerable training applications or authorized laboratory environments. The CyberNexa lab demonstrates the security concept using a simulated request flow rather than targeting real websites.

Module Summary

Trust Requests. Verify Intent.

CSRF occurs when an application accepts a sensitive authenticated request without sufficiently verifying that the request was intentionally generated by the legitimate application. CSRF tokens, appropriate cookie policies, origin validation and additional authentication controls help reduce this risk.
