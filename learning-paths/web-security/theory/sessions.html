01

What is a Web Session?

Core Definition

A web session is a period of interaction between a user and a web application. Because HTTP is fundamentally stateless, applications use session mechanisms to remember information about a user across multiple requests.

02

Why Sessions Are Needed

HTTP does not automatically remember that two requests came from the same authenticated user. A session mechanism allows the application to associate later requests with an existing user context.

This is especially important for login systems, shopping carts, dashboards, account settings and other personalized features.

03

How a Session Works

A common session flow works through a session identifier. The server creates a session and provides the browser with an identifier that can be sent with subsequent requests.

STEP 01

Login

The user submits valid authentication information.

STEP 02

Session Created

The server creates a session associated with the user.

STEP 03

Session ID

The browser receives a session identifier.

STEP 04

Requests

Later requests use the identifier to maintain context.

04

Session Identifier

A session identifier is a value used by the application to associate a browser with a server-side session. It should be unpredictable and protected because possession of a valid session identifier may allow access to the associated session.

HTTP/1.1 200 OK Set-Cookie: session_id=RANDOM_VALUE; Secure; HttpOnly
05

Session Security Controls

🔐
Secure Transport Sessions should be protected using HTTPS so that session information is not exposed over an insecure connection.
🛡
HttpOnly HttpOnly cookies reduce the ability of client-side scripts to directly access the cookie.
✓
Secure Cookie The Secure attribute instructs the browser to send the cookie over secure HTTPS connections.
⟳
Session Regeneration Applications should regenerate session identifiers when appropriate, especially around authentication state changes.
⏱
Session Expiration Sessions should expire after suitable periods of inactivity or according to application policy.
06

Common Session Security Risks

Poor session management can expose an application to attacks such as session hijacking, session fixation and session prediction. These problems generally occur when session identifiers are weak, exposed or improperly managed.

⚠ SECURITY REMINDER

Session identifiers should be treated as sensitive authentication-related information. Never expose real session tokens in screenshots, source code, logs or public repositories.

07

Session vs Cookie

A cookie is a browser-side storage mechanism that can contain information such as a session identifier. A session is the application's maintained interaction state, commonly stored on the server side.

Therefore, a session and a cookie are not the same thing. A cookie can be one mechanism used to maintain a session.

Module Summary

Maintain State. Protect the Session.

Web sessions allow applications to maintain user context across HTTP requests. Secure session management requires protected transport, strong and unpredictable identifiers, appropriate cookie attributes, session regeneration and sensible expiration. Understanding these controls is essential for secure web application development and testing.
