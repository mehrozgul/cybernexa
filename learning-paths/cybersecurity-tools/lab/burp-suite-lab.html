BURP SUITE PRACTICAL LAB

HTTP Request Analysis

Practice the core Burp Suite workflow by analyzing an HTTP request inside a controlled cybersecurity training environment.

Lab Objectives

  1. Understand the structure of an HTTP request.
  2. Identify the HTTP method and request path.
  3. Identify important HTTP headers.
  4. Modify a harmless test parameter.
  5. Analyze the simulated server response.

Step 1 — Capture a Request

In a real authorized Burp Suite environment, configure the browser to use Burp Proxy and browse your local training application. The request can then appear inside Proxy → HTTP history.

BURP-STYLE ANALYSIS
Click "Analyze Request" to inspect the request.

Step 2 — Repeater Practice

Change the value of the q parameter in the request. For example, replace the existing search term with another harmless test value and analyze the request again.

  • Observe the request path.
  • Identify the parameter.
  • Compare the request before and after the change.
  • Observe how a real application could return different content.

Step 3 — Real Burp Suite Workflow

For an actual local lab, create or use a deliberately vulnerable training application running on your own machine.

  1. Start Burp Suite.
  2. Open Burp's Proxy configuration.
  3. Configure your browser to use the local Burp proxy.
  4. Open your authorized local training application.
  5. Visit a page that generates an HTTP request.
  6. Open Proxy → HTTP history.
  7. Select the request.
  8. Send the request to Repeater.
  9. Change only harmless test parameters.
  10. Compare the resulting responses.
Example request:

GET /search?q=test HTTP/1.1
Host: lab.local

Example observation:

Method      : GET
Path        : /search
Parameter   : q
Value       : test
Protocol    : HTTP/1.1

Step 4 — Request Components

Method: GET Path: /search Parameter: q Parameter Value: test Host: lab.local Protocol: HTTP/1.1 These components are useful when understanding how web applications receive client requests.

Advanced Challenge

Build a small local training application and use Burp Suite to observe three different requests generated by it.

  • One GET request.
  • One POST request containing harmless test data.
  • One request containing a custom HTTP header.

For each request, document the method, path, parameters, headers and response status.
