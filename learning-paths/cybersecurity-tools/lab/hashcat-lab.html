HASHCAT PRACTICAL LAB

Password Hash Auditing

Learn the basic Hashcat workflow by creating and auditing a test hash that belongs to your own controlled laboratory environment.

Lab Objective

  1. Create a small local wordlist containing test values.
  2. Generate an MD5 hash from your own test value.
  3. Store the hash in a local hash file.
  4. Use Hashcat with the appropriate hash mode.
  5. Verify the result inside your authorized lab.

Step 1 — Create a Test Wordlist

Create a file named lab-wordlist.txt and put only your own test values inside it.

Linux Terminal
$ nano lab-wordlist.txt security123 CyberNexa123 training2026 testpass

Step 2 — Generate Your Test Hash

For this demonstration, use a test value that you created specifically for this lab.

Linux Terminal
$ printf "security123" | md5sum YOUR_GENERATED_HASH -

Replace YOUR_GENERATED_HASH with the hash produced by your own system.

Step 3 — Create the Hash File

Put your generated hash into a file named test-hash.txt.

Linux Terminal
$ nano test-hash.txt YOUR_GENERATED_HASH

Step 4 — Run Hashcat

MD5 uses Hashcat mode 0. Run this only against the test hash created for this lab.

Hashcat
$ hashcat -m 0 test-hash.txt lab-wordlist.txt

Step 5 — Display the Recovered Test Value

Hashcat Result
$ hashcat -m 0 test-hash.txt lab-wordlist.txt --show YOUR_GENERATED_HASH:security123

The exact output depends on the test value and the wordlist you created.

What Did You Learn?

  • A password can be represented by a hash.
  • Hashcat needs the correct hash mode.
  • A wordlist contains candidate values.
  • Hashcat compares candidates against the supplied hash.
  • Password auditing should be performed only on authorized test data.

Authorized Security Testing

Do not use Hashcat against passwords, hashes, accounts or systems that you do not own or have explicit permission to audit. The purpose of this CyberNexa exercise is to understand password security and defensive auditing in a controlled lab.
