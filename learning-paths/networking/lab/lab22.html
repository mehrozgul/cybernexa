🎯 Lab Objective

In this practical lab, you will learn how to identify and diagnose common network connectivity problems using a systematic troubleshooting process.

You will check your IP configuration, test the local gateway, test Internet connectivity, investigate the route to a destination and verify DNS resolution.

💡 What You Will Practice

ipconfig → check configuration → ping gateway → test local connectivity → ping public IP → test Internet → nslookup → test DNS → tracert → inspect network path.

01 Check IP Configuration

Open Command Prompt and run the following command. It displays the IPv4 address, subnet mask, default gateway and other network configuration information.

Windows Command Prompt
ipconfig /all
Example Output 
IPv4 Address. . . . . . . : 192.168.1.20
Subnet Mask . . . . . . . : 255.255.255.0
Default Gateway . . . . . : 192.168.1.1
DNS Servers . . . . . . . : 192.168.1.1
🔎 What to Observe

Find your active network adapter and identify the IPv4 address, subnet mask, default gateway and DNS server. Your actual values may be different.

02 Test the Default Gateway

The default gateway is normally the router that provides access from the local network to other networks. First identify your gateway from Step 01.

Command Prompt
ping 192.168.1.1
Expected Result 
Reply from 192.168.1.1: bytes=32 time<1ms TTL=64
Reply from 192.168.1.1: bytes=32 time<1ms TTL=64
Reply from 192.168.1.1: bytes=32 time<1ms TTL=64
Reply from 192.168.1.1: bytes=32 time<1ms TTL=64
🧠 Understand the Result

Successful replies indicate that the device can communicate with the gateway. If the gateway cannot be reached, investigate the local connection, IP configuration or Wi-Fi/Ethernet connection.

03 Test Internet Connectivity

After testing the local gateway, test a public IP address. This helps determine whether communication can leave the local network.

Command Prompt
ping 8.8.8.8
Example Result 
Reply from 8.8.8.8: bytes=32 time=25ms TTL=117
Reply from 8.8.8.8: bytes=32 time=24ms TTL=117
Reply from 8.8.8.8: bytes=32 time=26ms TTL=117
Reply from 8.8.8.8: bytes=32 time=25ms TTL=117
🔎 What to Observe

If the gateway responds but the public IP does not, the problem may be beyond the local network, such as routing, firewall filtering or Internet connectivity.

04 Test DNS Resolution

A device may have Internet connectivity but still be unable to open websites if DNS name resolution is not working correctly.

Command Prompt
nslookup google.com
Example Output 
Server:  router.local
Address:  192.168.1.1

Non-authoritative answer:
Name:    google.com
Addresses:  142.250.72.14
🧠 Understand the Result

If the domain name resolves to an IP address, DNS resolution is working for this test. If DNS fails while pinging a public IP works, investigate DNS configuration or DNS server availability.

05 Trace the Network Path

Use tracert to observe the path packets take toward a destination. This can help identify where communication may be failing.

Command Prompt
tracert 8.8.8.8
Example Output 
Tracing route to 8.8.8.8

  1    <1 ms    <1 ms    <1 ms    192.168.1.1
  2     8 ms     7 ms     8 ms    10.20.0.1
  3    18 ms    17 ms    19 ms    203.0.113.1
  4    25 ms    24 ms    25 ms    8.8.8.8

Trace complete.
🔎 What to Observe

The first hop is commonly the local gateway. Later hops represent routers along the path. Some routers may not respond to traceroute probes, so a timeout does not automatically mean the entire path is broken.

06 Check the ARP Table

ARP maps IPv4 addresses to MAC addresses on the local network. The ARP table can help when investigating local network communication.

Command Prompt
arp -a
Example Output 
Interface: 192.168.1.20

Internet Address      Physical Address      Type
192.168.1.1           aa-bb-cc-dd-ee-ff     dynamic
192.168.1.10          11-22-33-44-55-66     dynamic
🧠 Understand the Result

The table shows IP-to-MAC mappings known to the local system. A gateway entry can help confirm that the device has learned the gateway's Layer 2 address.

07 Complete the Troubleshooting Test

Now combine the previous commands and follow a systematic troubleshooting order instead of changing settings randomly.

Windows Command Prompt
ipconfig /all ping 192.168.1.1 ping 8.8.8.8 nslookup google.com tracert 8.8.8.8 arp -a
🧩 Troubleshooting Logic

Check configuration first → test the gateway → test Internet reachability → test DNS → inspect the route → inspect local ARP information.

🛠️ Common Troubleshooting Scenarios
Gateway Unreachable Check Wi-Fi/Ethernet, IP configuration, subnet mask and local gateway settings.
Internet IP Fails Check the gateway first, then investigate routing, firewall or Internet connectivity.
DNS Fails If a public IP responds but domain lookup fails, investigate DNS configuration.
Wrong IP Configuration Verify IPv4 address, subnet mask and default gateway using ipconfig.
Path Problem Use tracert to inspect the route toward the destination.
Local ARP Issue Use arp -a to inspect local IP-to-MAC address mappings.
# Key Concepts
IP Address Identifies a device at the network layer.
Subnet Mask Determines the network and host portions of an IPv4 address.
Default Gateway Provides a path from the local network toward other networks.
DNS Resolves domain names into IP addresses.
Ping Tests reachability using ICMP echo request and reply messages.
Traceroute Helps display the path toward a destination.
ARP Helps map IPv4 addresses to MAC addresses on the local network.
Connectivity Describes whether network communication between endpoints is working.
Systematic Troubleshooting A structured process used to locate the actual cause of a network problem.
📘 Practical Lab Summary

In this lab, you practiced a systematic approach to network troubleshooting using common Windows networking commands.

You checked IP configuration, tested the default gateway, tested Internet connectivity, verified DNS resolution, inspected the network path and viewed the ARP table.

These skills provide a basic foundation for network administration, troubleshooting and defensive cybersecurity analysis.

Learning Safety

Use networking commands only on systems and networks that you own or are explicitly authorized to inspect. These commands are intended for legitimate learning, administration and cybersecurity work.
