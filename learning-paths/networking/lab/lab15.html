📡 Port & Protocol Communication

A protocol defines how devices communicate, while a port identifies a logical endpoint used by a network application or service.

💡 Basic Idea

Think of an IP address as identifying a device and a port as identifying a particular service or communication endpoint on that device. The protocol defines the rules used for that communication.

01 What is a Port?

A port is a logical number used by TCP or UDP to identify a communication endpoint associated with an application or service.

🔎 Port Range

TCP and UDP each use port numbers from 0 through 65535. Ports are commonly grouped into well-known, registered and dynamic/private ranges.

Well-Known Ports Ports 0–1023. Common services such as HTTP, HTTPS, SSH and DNS use ports in this range.
Registered Ports Ports 1024–49151. Applications and services may register ports for specific purposes.
Dynamic / Private Ports 49152–65535 are commonly used for temporary client-side connections.
02 What is a Protocol?

A network protocol is a defined set of rules that determines how devices format, transmit and interpret data during communication.

🧠 Simple Example

HTTP defines rules for web communication. DNS defines how domain-name information is queried. SSH defines secure remote-access communication.

💡 Important

A port number alone does not guarantee which application is using it. The actual service should be verified from the system or network context.

04 View Ports with netstat

Windows netstat can display active network connections and listening ports.

Command Prompt
netstat -ano
Example Output 
Active Connections

  Proto  Local Address          Foreign Address        State           PID
  TCP    192.168.1.20:52144     142.250.72.14:443     ESTABLISHED     8420
  TCP    0.0.0.0:22             0.0.0.0:0             LISTENING       1200
  UDP    0.0.0.0:53             *:*                                   4200
🔎 What to Observe

Observe the protocol, local port, remote address, connection state and process ID. This information helps identify how the system is communicating.

05 Identify the Process Using a Port

The PID shown by netstat can be used with tasklist to identify the process associated with a connection or listening port.

Command Prompt
tasklist /FI "PID eq 1200"
Example Output 
Image Name                     PID
========================= ========
example-service.exe           1200
🧠 Why It Matters

Mapping a port to a process can help with troubleshooting and basic security investigation.

06 Test a TCP Port

PowerShell provides Test-NetConnection for checking TCP connectivity to a specific host and port.

PowerShell
Test-NetConnection google.com -Port 443
Example Output 
ComputerName     : google.com
RemoteAddress    : 142.250.72.14
RemotePort       : 443
InterfaceAlias   : Wi-Fi
TcpTestSucceeded : True
🔎 What to Understand

TcpTestSucceeded : True indicates that the TCP connection test to the specified destination port succeeded.

⚖️ TCP vs UDP Ports
TCP Port Used by TCP communication. TCP establishes connections and provides reliable delivery.
UDP Port Used by UDP communication. UDP is connectionless and has lower protocol overhead.
Same Number TCP and UDP can independently use the same numerical port because they are separate protocols.
Port 53 DNS commonly uses UDP 53 and can also use TCP 53 in situations requiring TCP.
Port 443 Traditionally associated with HTTPS over TCP; modern HTTP/3 uses QUIC over UDP.
Port + IP An IP address identifies a network endpoint while a transport port identifies a logical service endpoint.

🛡️ Why Ports & Protocols Matter in Cybersecurity

Security professionals examine ports and protocols to understand which services are communicating on a system or network.

Attack Surface Network-facing services can increase the attack surface of a system.
Monitoring Network traffic can be monitored to identify unusual communication patterns.
Troubleshooting Port and protocol information helps diagnose connectivity problems.
Firewall Rules Firewalls can use protocols and ports when controlling network traffic.
Service Identification Ports can provide clues about services operating on a system.
Incident Analysis Port and protocol information can support investigation of network activity.
🧠 Key Concepts
Port A logical communication endpoint identified by a number.
Protocol A set of rules used for network communication.
TCP Connection-oriented transport protocol with reliable and ordered delivery.
UDP Connectionless transport protocol with lower overhead and no guaranteed delivery.
Socket A communication endpoint commonly represented using an IP address and port.
Listening Port A local service endpoint waiting for incoming connection requests.

📘 Topic Summary

Ports are logical communication endpoints used by applications and services, while protocols define the rules used for communication.

TCP and UDP are the two major transport protocols. TCP provides connection-oriented and reliable communication, while UDP provides connectionless communication with lower overhead.

Understanding ports and protocols is essential for networking, troubleshooting and cybersecurity because network services communicate through these mechanisms.

🧪 Learning Safety

Use networking commands only on systems and networks that you own or are explicitly authorized to inspect. Port and service information should be used for legitimate learning, administration and security work.
