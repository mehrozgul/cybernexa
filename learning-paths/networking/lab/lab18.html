🎯 Lab Objective

In this practical lab, you will inspect your Windows network configuration, identify VPN-related interfaces, examine the routing table and verify network connectivity.

The commands are designed for your own computer and should be used only on systems and networks that you own or are authorized to inspect.

💡 What You Will Practice

ipconfig → identify network interfaces → route print → inspect routes → ping → test connectivity → tracert → observe packet path.

01 View Network Configuration

Open Command Prompt and run the following command. It displays the network interfaces and IP configuration of your Windows system.

Command Prompt
ipconfig /all
Example Output 
Ethernet adapter Ethernet:

   IPv4 Address. . . . . . : 192.168.1.20
   Subnet Mask . . . . . . : 255.255.255.0
   Default Gateway . . . . : 192.168.1.1

PPP adapter VPN:

   IPv4 Address. . . . . . : 10.8.0.6
🔎 What to Observe

Look for the active network adapters. A VPN may create an additional virtual adapter. The exact adapter name and IP address depend on the VPN software and configuration.

02 Identify VPN Network Interface

Use the Windows network configuration to identify whether a VPN-related virtual interface is present.

Command Prompt
ipconfig /all
🧠 Understand the Result

VPN applications can create virtual network adapters. Their names vary between VPN technologies and software. Do not assume that every additional adapter is a VPN; verify it using the VPN application's configuration.

03 View the Routing Table

The routing table shows how Windows decides where network traffic should be sent.

Command Prompt
route print
Example Output 
IPv4 Route Table

Network Destination     Netmask         Gateway
0.0.0.0                 0.0.0.0        10.8.0.5
10.8.0.0                255.255.255.0  On-link
192.168.1.0             255.255.255.0  On-link
🔎 Interpretation

The routing table contains destinations, masks and gateways/interfaces. VPN configurations can add or modify routes depending on whether they use full-tunnel or split-tunnel routing.

04 Test Basic Connectivity

Use ping to verify that your system can reach a destination over the current network configuration.

Command Prompt
ping 8.8.8.8
Example Output 
Pinging 8.8.8.8 with 32 bytes of data:

Reply from 8.8.8.8:
bytes=32 time=25ms TTL=117

Reply from 8.8.8.8:
bytes=32 time=24ms TTL=117
🧠 Understand the Result

A reply indicates that ICMP communication reached the destination and a response was received. A failed ping does not automatically mean that the VPN is not working, because ICMP may be blocked.

05 Trace the Network Path

Use tracert to observe the network path toward a destination.

Command Prompt
tracert 8.8.8.8
Example Output 
Tracing route to 8.8.8.8

  1    10.8.0.5
  2    172.16.0.1
  3    203.0.113.1
  4    8.8.8.8

Trace complete.
🔎 What to Observe

Observe the sequence of responding hops. The exact path will vary depending on your ISP, VPN provider, routing configuration and destination.

06 Check DNS Configuration

A VPN connection may also provide DNS configuration. Use the following command to inspect DNS settings.

Command Prompt
ipconfig /all | findstr /i "DNS Servers"
Example Output 
DNS Servers . . . . . . . . . . :
10.8.0.1
🛡️ Security Use

DNS configuration is important when troubleshooting VPN connectivity and investigating DNS-related behavior. The actual DNS server depends on the VPN and network setup.

07 Test a TCP Connection

PowerShell provides Test-NetConnection for testing TCP connectivity to a specific destination and port.

PowerShell
Test-NetConnection example.com -Port 443
Example Output 
ComputerName     : example.com
RemotePort       : 443
InterfaceAlias   : Wi-Fi
TcpTestSucceeded : True
🧠 Understand the Result

TcpTestSucceeded : True means that the TCP connection test succeeded. The InterfaceAlias shows the interface Windows used for the connection in that test.

08 Mini VPN Investigation

Complete this short investigation on your own Windows system. Perform the checks before and after connecting to your VPN and compare the results.

🧪 Task

1. Run ipconfig /all before connecting to VPN.
2. Connect to your VPN.
3. Run ipconfig /all again.
4. Run route print.
5. Identify any new VPN-related interface or route.
6. Run ping 8.8.8.8.
7. Run tracert 8.8.8.8.
8. Compare the results before and after the VPN connection.

🔐 VPN Concepts — Practical Understanding
VPN Client Software that establishes and manages the VPN connection on a user's device.
VPN Server The VPN endpoint that accepts the client's VPN connection.
VPN Tunnel A logical protected connection through which network traffic can be transported.
Encryption Protects data transmitted through the VPN connection from unauthorized reading.
Full Tunnel A configuration in which VPN routing can send most or all network traffic through the VPN.
Split Tunnel A configuration where selected traffic uses the VPN while other traffic uses the normal connection.
⚖️ Full Tunnel vs Split Tunnel
Full Tunnel Network traffic is generally routed through the VPN connection according to the VPN configuration.
Split Tunnel Only selected destinations or traffic use the VPN, while other traffic uses the normal route.
Routing Table The routing table helps determine which interface and gateway are used for a destination.
Virtual Adapter VPN software may create a virtual network interface used to transport VPN traffic.
DNS VPN configurations may provide or route DNS queries through specific DNS servers.
Encryption VPN protocols can use cryptographic mechanisms to protect traffic between VPN endpoints.
🛡️ Cybersecurity Application

VPN knowledge is important for cybersecurity professionals because VPNs affect network visibility, routing, remote access and traffic analysis.

Remote Access Organizations can use VPNs to provide authorized users with secure access to internal resources.
Traffic Analysis Security analysts need to understand how VPN routing can change the apparent path of network traffic.
Network Monitoring VPN interfaces and routes can be relevant when investigating network activity.
Access Control VPN access can be combined with authentication and authorization controls.
Incident Investigation Investigators may need VPN connection information when analyzing remote network activity.
Security Limitation A VPN protects the VPN connection but does not automatically make every application or endpoint secure.
🛠️ Troubleshooting

If the VPN does not appear to work correctly, check the configuration logically instead of changing multiple settings at the same time.
