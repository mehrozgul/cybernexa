🎯 Lab Objective

In this practical lab, you will divide one physical switch into three logical networks using VLAN 10, VLAN 20 and VLAN 30.

You will assign switch ports to the correct VLANs, configure a trunk connection to the router and use router-on-a-stick to allow controlled communication between the VLANs.

💡 What You Will Learn

You will practice VLAN creation, access ports, trunk ports, 802.1Q tagging, router subinterfaces, inter-VLAN routing and basic VLAN verification.

01 Create the VLANs

Open the CLI of SW1 and create the three VLANs with meaningful names.

Cisco IOS — SW1
enable configure terminal vlan 10 name HR vlan 20 name FINANCE vlan 30 name IT end
Verification 
show vlan brief

10   HR
20   FINANCE
30   IT
🧠 Understand the Result

The switch now has three logical VLANs. Each VLAN represents a separate Layer 2 broadcast domain.

02 Configure Access Ports

Assign end-device ports to their respective VLANs. In this example, Fa0/1–Fa0/2 belong to HR, Fa0/3–Fa0/4 belong to Finance and Fa0/5–Fa0/6 belong to IT.

Cisco IOS — SW1
enable configure terminal interface range fa0/1 - 2 switchport mode access switchport access vlan 10 exit interface range fa0/3 - 4 switchport mode access switchport access vlan 20 exit interface range fa0/5 - 6 switchport mode access switchport access vlan 30 end
🔎 Important

An access port normally carries traffic for one VLAN. End devices such as PCs are commonly connected through access ports.

03 Configure the Trunk Port

Configure Fa0/24 as the trunk link between SW1 and R1. The trunk carries VLAN 10, 20 and 30 traffic.

Cisco IOS — SW1
enable configure terminal interface fa0/24 switchport mode trunk switchport trunk allowed vlan 10,20,30 end
Example Verification 
show interfaces trunk

Port        Mode        Status
Fa0/24      trunk       trunking

Vlans allowed on trunk
10,20,30
🔗 Why a Trunk?

A trunk can carry traffic for multiple VLANs over one physical link. VLAN information is commonly identified with IEEE 802.1Q tagging.

04 Configure Router-on-a-Stick

Configure router subinterfaces on R1. Each subinterface acts as the Layer 3 gateway for one VLAN.

Cisco IOS — R1
enable configure terminal interface g0/0 no shutdown exit interface g0/0.10 encapsulation dot1q 10 ip address 192.168.10.1 255.255.255.0 exit interface g0/0.20 encapsulation dot1q 20 ip address 192.168.20.1 255.255.255.0 exit interface g0/0.30 encapsulation dot1q 30 ip address 192.168.30.1 255.255.255.0 end
Example Verification 
show ip interface brief

GigabitEthernet0/0.10   192.168.10.1   up   up
GigabitEthernet0/0.20   192.168.20.1   up   up
GigabitEthernet0/0.30   192.168.30.1   up   up

Configure each PC with an IP address from the correct VLAN network and use the router subinterface as the default gateway.

💡 Packet Tracer

On each PC, open Desktop → IP Configuration and enter the corresponding IP address, subnet mask and default gateway.

06 Verify VLAN Configuration

Use the following commands on SW1 to verify VLAN membership and trunk configuration.

Cisco IOS — SW1
show vlan brief show interfaces trunk
What to Check 
VLAN 10 → Fa0/1, Fa0/2
VLAN 20 → Fa0/3, Fa0/4
VLAN 30 → Fa0/5, Fa0/6

Trunk → Fa0/24
Allowed VLANs → 10,20,30
07 Test Connectivity

First test communication between PCs in the same VLAN. Then test communication between different VLANs.

PC Command Prompt
ping 192.168.10.11 ping 192.168.20.10 ping 192.168.30.10
Expected Result 
Reply from 192.168.10.11: bytes=32 time<1ms TTL=128
Reply from 192.168.20.10: bytes=32 time<1ms TTL=128
Reply from 192.168.30.10: bytes=32 time<1ms TTL=128
🧠 Understand the Result

Successful cross-VLAN ping shows that the switch trunk, router subinterfaces, IP addressing and inter-VLAN routing are working together.

🛠️ Common Troubleshooting
Wrong VLAN Check that the PC switch port is assigned to the correct VLAN.
Trunk Problem Check that Fa0/24 is configured as a trunk and allows VLANs 10, 20 and 30.
Gateway Problem Check that each PC uses the gateway for its own VLAN.
Router Interface Check that G0/0 is enabled and the subinterfaces are up with correct 802.1Q VLAN IDs.
IP Address Confirm that the PC IP address belongs to the correct VLAN subnet.
Verification Use show vlan brief, show interfaces trunk and show ip interface brief.
🛡️ Why VLANs Matter in Cybersecurity

VLANs are commonly used as part of network segmentation. Segmentation can help separate users, servers, guest systems and security-sensitive resources.

Segmentation Separates groups of devices into different logical broadcast domains.
Access Control Inter-VLAN traffic can be controlled with Layer 3 security policies and ACLs.
Reduced Broadcast Scope Broadcast traffic stays within its VLAN unless Layer 3 forwarding is used.
Guest Isolation Guest devices can be placed in a separate VLAN from internal resources.
Monitoring Segmented networks can make traffic boundaries easier to understand during security monitoring.
Layer 2 Security VLAN configuration is one part of a broader switch security strategy.

🧠 Key Concepts
VLAN A logical network created inside a physical switching infrastructure.
VLAN ID A numerical identifier used to distinguish VLANs.
Access Port A switch port normally assigned to one VLAN for an end device.
Trunk Port A link that carries traffic for multiple VLANs.
802.1Q A standard commonly used to identify VLAN traffic across trunk links.
Inter-VLAN Routing Layer 3 forwarding that allows devices in different VLANs to communicate.
📘 Practical Lab Summary

In this lab, you created three logical networks using VLAN 10, VLAN 20 and VLAN 30 on a Cisco switch.

You assigned access ports, configured a trunk link and created router subinterfaces using 802.1Q encapsulation.

You then configured IP addressing and verified same-VLAN and inter-VLAN connectivity using show commands and ping.
