Firewall

Build a simple network, configure a Cisco router as a basic firewall using an extended ACL, control traffic by protocol and port, and verify allowed and blocked traffic.

🎯 Lab Objective

In this practical lab, you will create two simple networks connected through a Cisco router.

You will configure an extended Access Control List (ACL) to control traffic according to IP addresses, protocols and destination ports.

💡 What You Will Learn

You will learn how a router can enforce basic firewall-like traffic rules. The lab demonstrates protocol and port-based filtering using TCP and ICMP.

01 IP Addressing Plan

Configure all devices according to the following addressing plan.

Device Interface IP Address Subnet Mask Gateway
PC1 FastEthernet0 192.168.10.10 255.255.255.0 192.168.10.1
SW1 VLAN 1 192.168.10.2 255.255.255.0 192.168.10.1
R1 G0/0 192.168.10.1 255.255.255.0 —
R1 G0/1 192.168.20.1 255.255.255.0 —
Server FastEthernet0 192.168.20.10 255.255.255.0 192.168.20.1
02 Configure PC and Server

Open each device in Packet Tracer and go to Desktop → IP Configuration.

💻 PC1

IP Address: 192.168.10.10
Subnet Mask: 255.255.255.0
Default Gateway: 192.168.10.1

🖥️ Server

IP Address: 192.168.20.10
Subnet Mask: 255.255.255.0
Default Gateway: 192.168.20.1

03 Configure the Switch

Open SW1 → CLI and configure basic switch settings.

Cisco IOS — SW1
enable configure terminal hostname SW1 no ip domain-lookup enable secret class service password-encryption line console 0 password cisco login exit interface vlan 1 ip address 192.168.10.2 255.255.255.0 no shutdown exit ip default-gateway 192.168.10.1 interface range fa0/1, fa0/24 switchport mode access no shutdown exit end write memory
Verify 
show ip interface brief
show interfaces status
04 Configure the Router

Open R1 → CLI and configure the router hostname and basic security settings.

Cisco IOS — R1
enable configure terminal hostname R1 no ip domain-lookup enable secret class service password-encryption line console 0 password cisco login exit
05 Configure Router Interfaces

Configure both router interfaces. G0/0 connects to the client network and G0/1 connects to the server network.

Cisco IOS — R1
enable configure terminal interface gigabitEthernet 0/0 description CLIENT-LAN ip address 192.168.10.1 255.255.255.0 no shutdown exit interface gigabitEthernet 0/1 description SERVER-LAN ip address 192.168.20.1 255.255.255.0 no shutdown exit end write memory
Verify Router Interfaces 
show ip interface brief
📌 Expected State

G0/0 should be 192.168.10.1 and G0/1 should be 192.168.20.1. Both interfaces should become up/up when the physical connections are correct.

06 Test Connectivity Before Firewall Rules

First verify that the client can reach the server before applying the firewall ACL.

PC1 — Command Prompt
ping 192.168.10.1 ping 192.168.20.1 ping 192.168.20.10
Expected 
Reply from 192.168.10.1:
Reply from 192.168.20.1:
Reply from 192.168.20.10:

At this stage, the networks should communicate normally.
07 Enable Server Services

Open the Server in Packet Tracer and go to Services. Enable HTTP and HTTPS so that the firewall rules can control web traffic.

🖥️ Server → Services

HTTP: ON
HTTPS: ON

🌐 Test Web Service

From PC1 open Desktop → Web Browser and test:

http://192.168.20.10
https://192.168.20.10

08 Create Firewall Access List

Now create an extended ACL that controls traffic from the client network toward the server network.

Cisco IOS — R1
enable configure terminal ip access-list extended FIREWALL-ACL permit tcp 192.168.10.0 0.0.0.255 host 192.168.20.10 eq 80 permit tcp 192.168.10.0 0.0.0.255 host 192.168.20.10 eq 443 deny tcp 192.168.10.0 0.0.0.255 host 192.168.20.10 eq 22 permit icmp 192.168.10.0 0.0.0.255 host 192.168.20.10 deny ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255 exit
🔎 Firewall Rules Explained

TCP port 80 → HTTP → ALLOW
TCP port 443 → HTTPS → ALLOW
TCP port 22 → SSH → BLOCK
ICMP → Ping → ALLOW
Other IP traffic between the two networks → BLOCK

09 Apply Firewall Rule to Interface

Apply the ACL outbound on R1 G0/1 so that traffic going toward the server network is filtered.

Cisco IOS — R1
enable configure terminal interface gigabitEthernet 0/1 ip access-group FIREWALL-ACL out exit end write memory
Verify ACL 
show access-lists
show ip interface gigabitEthernet 0/1
10 Verify Firewall Rules

Use the following command to see the ACL entries and packet counters.

Cisco IOS — R1
show access-lists FIREWALL-ACL
What to Observe 
Extended IP access list FIREWALL-ACL
permit tcp ... eq 80
permit tcp ... eq 443
deny tcp ... eq 22
permit icmp ...
deny ip ...

Packet counters increase when matching traffic is generated.
11 Test Ports and Protocols

The firewall makes decisions according to the protocol and destination port defined in the ACL.

Service Protocol Port Firewall Action
HTTP TCP 80 ALLOW
HTTPS TCP 443 ALLOW
SSH TCP 22 BLOCK
Ping ICMP No Port ALLOW
Other IP Traffic IP — BLOCK
12 Test Firewall Behavior

Test the traffic after applying the firewall ACL.

PC1 — Command Prompt
ping 192.168.20.10
Expected 
Reply from 192.168.20.10:

ICMP is allowed by the firewall rule.
🌐 HTTP / HTTPS Test

From PC1 → Desktop → Web Browser:

http://192.168.20.10
https://192.168.20.10

These services are permitted because TCP ports 80 and 443 are allowed.

🔐 SSH Test

TCP port 22 is explicitly denied by the firewall ACL. Therefore, SSH traffic toward the protected server should not be permitted by this ACL.

13 Check Firewall Counters

Generate some traffic and then check the ACL again. The counters help show which rules have matched traffic.

Cisco IOS — R1
show access-lists FIREWALL-ACL
🧠 What to Observe

After testing HTTP, HTTPS and ICMP, the packet counters for the matching permit rules should increase. Blocked traffic can increase the deny-rule counter.

⚙️ Firewall Rule Logic
Source IP Identifies where the traffic originates. This lab uses the 192.168.10.0/24 client network.
Destination IP Identifies the protected destination. The server uses 192.168.20.10.
Protocol ACL rules can match protocols such as TCP and ICMP.
Port TCP destination ports identify services such as HTTP 80, HTTPS 443 and SSH 22.
Permit A permit rule allows traffic that matches the specified conditions.
Deny A deny rule prevents matching traffic from passing through the interface.
🛠️ Troubleshooting

If the expected traffic is not working, check the configuration in a logical order.

🛡️ Why Firewall Knowledge Matters in Cybersecurity

Cybersecurity professionals need to understand how network traffic is controlled before analyzing attacks, suspicious connections or unauthorized access.

Traffic Filtering Firewalls can allow or block traffic according to security rules.
Access Control ACLs can restrict communication between network segments.
Port Security Ports can be controlled to limit access to specific services.
Protocol Filtering Security rules can distinguish TCP, UDP and ICMP traffic.
Network Segmentation Separate networks can be protected using traffic-control rules.
Incident Analysis Firewall rules and logs help security professionals understand network traffic.

ACL An Access Control List contains permit and deny traffic rules.
TCP A transport protocol used by services such as HTTP, HTTPS and SSH.

Port 80 Common destination port associated with HTTP.
Port 443 Common destination port associated with HTTPS.
Port 22 Common destination port associated with SSH.
Permit Allows traffic that matches the ACL rule.
Deny Blocks traffic that matches the ACL rule.
📘 Practical Lab Summary

In this lab, you created a small network containing a client PC, switch, router and server.

You configured an extended ACL on the router and used IP addresses, protocols and destination ports to control network traffic.

HTTP and HTTPS traffic were permitted, SSH traffic was blocked, and ICMP traffic was permitted for connectivity testing.

You also verified the firewall configuration using Cisco IOS show commands and ACL packet counters.
