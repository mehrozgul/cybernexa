🎯 Lab Objective

In this lab, you will learn the practical difference between TCP and UDP transport protocols.

You will use Windows networking commands to observe TCP connections, TCP listening ports and UDP endpoints.

📡 TCP vs UDP Communication

TCP is connection-oriented and provides reliable, ordered delivery of data. UDP is connectionless and sends datagrams without establishing a connection.

💡 Basic Idea

TCP establishes a connection before data transfer and uses mechanisms such as acknowledgements and retransmission. UDP sends datagrams without creating a connection first.

01 View Active TCP Connections

Use netstat to display active TCP connections on your Windows computer.

Command Prompt
netstat -ano -p tcp
Example Output 
Active Connections

  Proto  Local Address          Foreign Address        State           PID
  TCP    192.168.1.20:52144     142.250.72.14:443     ESTABLISHED     8420
  TCP    192.168.1.20:52145     142.250.72.14:443     ESTABLISHED     8420
  TCP    192.168.1.20:52146     192.168.1.1:443       TIME_WAIT       0
🔎 What to Observe

Look at the Proto, Local Address, Foreign Address and State columns. TCP connections can have states such as ESTABLISHED, LISTENING and TIME_WAIT.

02 View TCP Listening Ports

The following command displays TCP ports that are currently listening for incoming connections.

Command Prompt
netstat -ano -p tcp | findstr LISTENING
Example Output 
TCP    0.0.0.0:135        0.0.0.0:0        LISTENING    1200
TCP    0.0.0.0:445        0.0.0.0:0        LISTENING    4
TCP    127.0.0.1:3306     0.0.0.0:0        LISTENING    5620
💡 Concept

LISTENING means that a TCP socket is waiting for incoming connection requests on that local port.

03 Test a TCP Port

PowerShell provides Test-NetConnection for testing TCP connectivity to a specific host and port.

PowerShell
Test-NetConnection google.com -Port 443
Example Output 
ComputerName     : google.com
RemoteAddress    : 142.250.72.14
RemotePort       : 443
InterfaceAlias   : Wi-Fi
TcpTestSucceeded : True
🔎 What to Understand

TcpTestSucceeded : True means the TCP connection test to the specified destination port succeeded.

04 View UDP Endpoints

UDP does not use connection states like TCP. Use netstat to view UDP endpoints currently present on the system.

Command Prompt
netstat -ano -p udp
Example Output 
Active Connections

  Proto  Local Address          Foreign Address        State           PID
  UDP    0.0.0.0:53             *:*                                    4200
  UDP    0.0.0.0:1900           *:*                                    1180
  UDP    192.168.1.20:5353      *:*                                    5620
💡 Important

UDP is connectionless, so netstat does not show TCP-style states such as ESTABLISHED or LISTENING for UDP endpoints.

05 View UDP Endpoints with PowerShell

PowerShell can provide a more direct view of UDP endpoints using Get-NetUDPEndpoint.

PowerShell
Get-NetUDPEndpoint | Select-Object LocalAddress,LocalPort,OwningProcess
Example Output 
LocalAddress   LocalPort   OwningProcess
------------   ---------   -------------
0.0.0.0        53          4200
0.0.0.0        1900        1180
127.0.0.1      5353        5620
🔎 What to Observe

Observe the local UDP address, port and process ID. UDP endpoints can exist without an established connection.

06 Identify TCP and UDP by Port

You can search netstat output for a specific port to determine whether it appears under TCP or UDP.

Command Prompt
netstat -ano | findstr :53
Example Output 
UDP    0.0.0.0:53       *:*       4200
🧠 What to Understand

The first column identifies the transport protocol. TCP and UDP can use the same port number independently because they are separate transport protocols.

⚖️ TCP vs UDP Practical Comparison
Connection TCP establishes a connection before transferring application data. UDP does not establish a connection.
Reliability TCP provides reliable and ordered delivery. UDP does not guarantee delivery or ordering.
Speed / Overhead TCP has more protocol overhead. UDP has a smaller header and generally lower communication overhead.
TCP Example HTTPS commonly uses TCP port 443 for traditional HTTP/1.1 and HTTP/2 connections.
UDP Example DNS commonly uses UDP port 53 for standard DNS queries.
Practical Tool netstat can display both TCP connections and UDP endpoints on Windows.

🧠 Key TCP and UDP Concepts
TCP Transmission Control Protocol is a connection-oriented transport protocol.
UDP User Datagram Protocol is a connectionless transport protocol.
Port A logical transport-layer identifier used to associate network traffic with applications.
LISTENING A TCP socket state indicating that the system is waiting for incoming connections.
ESTABLISHED A TCP state indicating that a connection has been established between endpoints.
Datagram A self-contained UDP message sent without establishing a transport connection.

📘 Lab Summary

In this practical lab, you explored TCP and UDP, two major transport-layer protocols.

You used netstat and PowerShell commands to observe TCP connections, TCP listening ports and UDP endpoints. You also practiced testing TCP connectivity with Test-NetConnection.

The main difference is that TCP is connection-oriented and provides reliable, ordered delivery, while UDP is connectionless and does not provide those TCP reliability mechanisms at the transport layer.

Lab Safety

Perform these exercises only on systems and networks that you own or are explicitly authorized to inspect. The commands in this lab are intended for basic network observation, learning and troubleshooting.
