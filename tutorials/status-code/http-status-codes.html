HTTP Status Codes Explained

Understand how web servers communicate the result of HTTP requests using 1xx, 2xx, 3xx, 4xx and 5xx status codes — and learn how these responses are interpreted during web development, troubleshooting and security analysis.

What is HTTP?

HTTP stands for Hypertext Transfer Protocol. It is an application-layer protocol used for communication between clients and servers on the Web.

A browser or other client sends an HTTP request to a server. The server processes the request and returns an HTTP response.

What is an HTTP Status Code?

An HTTP status code is a three-digit number included in an HTTP response. It provides a general indication of what happened when the server processed the request.

HTTP/1.1 200 OK

The first digit identifies the broad category of the response.

The Five HTTP Status Code Classes

1xx

Informational

The request has been received or understood and the process is continuing.

2xx

Success

The request was successfully received, understood and processed.

3xx

Redirection

The client needs to take additional action, often involving another resource or location.

4xx

Client Errors

The request could not be fulfilled because of something associated with the request.

5xx

Server Errors

The server encountered an error while processing an apparently valid request.

1xx — Informational Responses

1xx responses provide informational feedback while a request is being processed.

100 Continue

Indicates that the initial part of a request has been received and the client can continue sending the request.

HTTP/1.1 100 Continue

101 Switching Protocols

Indicates that the server is switching protocols according to the client's request.

2xx — Successful Responses

200 OK

The request was successfully processed.

HTTP/1.1 200 OK

201 Created

The request succeeded and resulted in creation of a new resource.

HTTP/1.1 201 Created

204 No Content

The request was successfully processed but there is no response content to return.

HTTP/1.1 204 No Content
Security relevance: A successful HTTP response does not automatically mean that an application is secure. Authorization and application logic must still be evaluated.

3xx — Redirection

301 Moved Permanently

Indicates that a resource has been permanently moved to another URL.

HTTP/1.1 301 Moved Permanently Location: https://example.com/new-page

302 Found

Indicates a temporary redirection.

304 Not Modified

Indicates that the cached representation can be used because the resource has not changed according to the request's caching conditions.

4xx — Client Error Responses

400 Bad Request

The server cannot process the request because the request is invalid or malformed.

HTTP/1.1 400 Bad Request

401 Unauthorized

The request lacks valid authentication credentials for the requested resource.

HTTP/1.1 401 Unauthorized

403 Forbidden

The server understood the request but refuses to fulfill it.

HTTP/1.1 403 Forbidden

404 Not Found

The server cannot find the requested resource.

HTTP/1.1 404 Not Found

405 Method Not Allowed

The request method is known but is not allowed for the target resource.

HTTP/1.1 405 Method Not Allowed Allow: GET, HEAD

429 Too Many Requests

The client has sent too many requests within a specified period. It is commonly associated with rate limiting.

HTTP/1.1 429 Too Many Requests

5xx — Server Error Responses

500 Internal Server Error

A generic server-side error occurred.

HTTP/1.1 500 Internal Server Error

502 Bad Gateway

A server acting as a gateway or proxy received an invalid response from an upstream server.

503 Service Unavailable

The server is currently unable to handle the request, commonly because of temporary overload or maintenance.

HTTP/1.1 503 Service Unavailable

504 Gateway Timeout

A gateway or proxy did not receive a timely response from an upstream server.

HTTP Status Codes in Cybersecurity

Security professionals often examine HTTP status codes while analyzing web applications, logs and server behavior.

  • 200 can indicate that a requested resource was successfully returned.
  • 301/302 can reveal redirects and application navigation behavior.
  • 401 can indicate that authentication is required.
  • 403 can indicate that access to a resource is being denied.
  • 404 can help identify nonexistent resources during normal troubleshooting.
  • 429 can indicate that rate limiting is being applied.
  • 500-series responses can indicate server-side problems that require investigation.

Reading an HTTP Response

HTTP/1.1 200 OK Content-Type: text/html Content-Length: 1250 Server: ExampleServer <html> ... </html>

The first line contains the HTTP version, status code and reason phrase.

The following lines are HTTP headers. After the headers, the response body may contain the requested content.

Checking Status Codes with curl

On a Linux system, curl can be used to inspect HTTP responses from an authorized server.

curl -I https://example.com

A response may contain:

HTTP/1.1 200 OK Content-Type: text/html

The -I option requests response headers without downloading the normal response body.

Understanding 401 vs 403

401

Authentication Problem

The request does not have valid authentication credentials for the protected resource.

403

Access Refused

The server understood the request but refuses to authorize access.

Easy memory trick: Think about 401 in terms of authentication and 403 in terms of permission/access refusal.

Common Mistakes

  • Thinking every 4xx response means the server is broken.
  • Treating 401 and 403 as exactly the same thing.
  • Assuming 200 always means the requested application operation was logically successful.
  • Assuming a 404 always means the entire website is down.
  • Ignoring HTTP response headers when troubleshooting.
  • Assuming a 500 response alone proves a vulnerability.
