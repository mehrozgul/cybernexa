HTTP Status Codes Lab

Practice HTTP response analysis using curl, inspect response headers, identify common HTTP status codes and understand how different responses appear to a client.

LEVEL Beginner
CATEGORY Web Security
PLATFORM Linux / Terminal

Lab Objectives

In this lab you will practice the HTTP concepts covered in the tutorial.

  • Send HTTP requests using curl.
  • Inspect HTTP response headers.
  • Identify 2xx successful responses.
  • Identify 3xx redirection responses.
  • Understand 4xx client-error responses.
  • Understand 5xx server-error responses.
  • Compare 401 and 403 responses.
  • Understand the meaning of 404 and 429.
  • Read an HTTP response structure.
  • Perform a basic HTTP security-oriented analysis.
Authorization: Perform HTTP testing only against websites, applications and systems that you own or are explicitly authorized to test.

Task 01 — Inspect a Successful HTTP Response

1

Check a 200 OK response

Use curl with the -I option to request the HTTP response headers.

COMMAND 
curl -I https://example.com
Example Output
HTTP/1.1 200 OK Content-Type: text/html Content-Length: ...

The important part is the status line:

HTTP/1.1 200 OK

This indicates that the server successfully processed the request.

Task 02 — Inspect HTTP Headers

2

Understand response headers

Run: 

curl -I https://example.com

Look for headers such as:

HTTP/1.1 200 OK Content-Type: text/html Content-Length: ... Server: ...

What should you identify?

  • HTTP version
  • Status code
  • Content-Type
  • Content-Length, if provided
  • Other response headers
Security connection: HTTP headers can provide useful information during legitimate web application analysis.

Task 03 — Test a 404 Not Found Response

3

Request a nonexistent resource

Use a clearly nonexistent path on the test domain: 

curl -I https://example.com/this-page-does-not-exist

You may receive a response similar to:

HTTP/1.1 404 Not Found

A 404 response means that the server could not find the requested resource.

Important: A 404 does not mean that the entire website is unavailable. It normally refers to the requested resource.

Task 04 — Understand Redirects

4

Inspect redirect behavior

Run: 

curl -I http://example.com

A server may respond with a redirect such as:

HTTP/1.1 301 Moved Permanently Location: https://example.com/

Follow Redirects

Use -L to tell curl to follow redirects: 

curl -I -L http://example.com
Remember: 301 indicates a permanent redirect, while 302 generally indicates a temporary redirect.

Task 05 — Understand 401 Unauthorized

5

Authentication-related response

A 401 response indicates that the request does not contain valid authentication credentials for the requested protected resource.

HTTP/1.1 401 Unauthorized

Practice Question

If a protected resource requires authentication and the request does not provide valid credentials, which status code should you understand first?

401

Authentication

Used when valid authentication credentials are missing or not accepted.

403

Access Refused

The server understood the request but refuses to authorize access.

Task 06 — Understand 403 Forbidden

6

Authorization-related response

A 403 response indicates that the server understood the request but refuses to fulfill it.

HTTP/1.1 403 Forbidden

401 vs 403

401

Authentication

The client lacks valid authentication credentials for the resource.

403

Authorization

The server understands the request but refuses access.

Easy memory trick: 401 → Authentication
403 → Access / Authorization refusal

Task 07 — Understand 405 Method Not Allowed

7

Understand allowed HTTP methods

A 405 response means the HTTP method is known but is not allowed for the requested resource.

HTTP/1.1 405 Method Not Allowed Allow: GET, HEAD

The Allow header may indicate which methods are supported.

Security connection: Understanding HTTP methods is important when analyzing how a web application handles requests.

Task 08 — Understand 429 Too Many Requests

8

Understand rate limiting

A 429 response indicates that the client has sent too many requests within a specified period.

HTTP/1.1 429 Too Many Requests

This status is commonly associated with rate-limiting controls.

Security connection: Rate limiting can help applications control excessive request activity.

Task 09 — Understand 5xx Server Errors

9

Identify server-side response classes

5xx responses indicate that the server encountered a problem while processing the request.

500

Internal Server Error

Generic server-side error.

502

Bad Gateway

Invalid response from an upstream server.

503

Service Unavailable

Server temporarily cannot handle the request.

504

Gateway Timeout

Gateway or proxy did not receive a timely upstream response.

Explain

Goal: Do not just memorize status codes. Learn to look at an HTTP response and interpret what the server is communicating to the client.

Understand a Complete HTTP Response

HTTP/1.1 200 OK Content-Type: text/html Content-Length: 1250 Server: ExampleServer <html> ... </html>
HTTP Version
→
Status Code
→
Headers
→
Response Body
  • HTTP/1.1 → protocol version
  • 200 → status code
  • OK → reason phrase
  • Content-Type → type of returned content
  • Content-Length → size information
  • Response body → actual returned content

Practical Security Analysis

HTTP status codes can provide useful context during authorized web application troubleshooting and security analysis.

200

Success

The request was successfully processed.

301 / 302

Redirect

The response directs the client toward another resource or location.

401

Authentication

Valid authentication credentials are required or were not accepted.

403

Access Refused

The server refuses to authorize access.

404

Resource Not Found

The requested resource could not be found.

429

Rate Limiting

Too many requests have been received within the applicable limit.
